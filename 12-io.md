Потоки ввода-вывода

При запуске программы Linux предоставляет ей стандартные каналы для обмена данными с внешним миром. В простейшем случае программа может получать данные на вход, выводить результаты и сообщать об ошибках.

В Linux для этого используются три стандартных потока:

stdin   - стандартный ввод
stdout  - стандартный вывод
stderr  - стандартный поток ошибок

Именно эти потоки позволяют перенаправлять вывод команд в файлы, передавать результат одной программы другой и скрывать ненужные сообщения.



Стандартные потоки

Стандартный ввод - stdin

stdin используется программой для получения входных данных.

По умолчанию источником stdin является клавиатура.

Например:

> cat

После запуска cat ждёт ввода:

> cat
Hello
Hello
Test
Test

Введённая строка передаётся программе через стандартный ввод, а cat выводит её обратно.



Стандартный вывод - stdout

stdout используется для обычного результата работы программы.

Например:

> echo "Hello"

Результат:

Hello

По умолчанию stdout направлен в терминал.



Стандартный поток ошибок - stderr

stderr используется для сообщений об ошибках и других диагностических сообщений.

Например:

> cat nonexistent.txt

может вывести:

cat: nonexistent.txt: No such file or directory

Сообщение также появляется в терминале, но технически оно отправлено не в stdout, а в stderr.

Это различие становится важным при перенаправлении вывода.



Файловые дескрипторы

Три стандартных потока имеют номера, называемые файловыми дескрипторами:

0 - stdin
1 - stdout
2 - stderr



Файловый дескриптор - это уникальный числовой идентификатор (целое неотрицательное число), который операционная система назначает открытому файлу, каталогу, сокету или любому другому потоку ввода-вывода, чтобы затем взаимодействовать с ним.

Поэтому можно встретить записи:

> command > output.txt

и:

> command 1> output.txt

Это одно и то же: в обоих случаях перенаправляется stdout.

А:

> command 2> errors.txt

перенаправляет stderr.



Перенаправление вывода

Оператор > направляет стандартный вывод команды в файл:

> echo "Hello" > output.txt

Теперь:

> cat output.txt

выведет:

Hello

Если файл уже существовал, его содержимое будет перезаписано.



Добавление в конец файла

Оператор:

>>

добавляет данные в конец файла:

> echo "Second line" >> output.txt

Теперь файл содержит:

Hello
Second line

Разница:

>    создать / перезаписать
>>   добавить в конец



Перенаправление ввода

Оператор < позволяет взять стандартный ввод из файла.

Например:

> wc -l < file.txt

В этом случае содержимое file.txt передаётся программе через stdin.

Упрощённо:

file.txt
   ↓
 stdin
   ↓
  wc

Некоторые команды умеют принимать файл непосредственно аргументом:

> wc -l file.txt

Поэтому < на практике используется реже, но понимание принципа важно.



Перенаправление ошибок

Чтобы перенаправить stderr:

> command 2> errors.txt

Например:

> cat existing.txt nonexistent.txt 2> errors.txt

Обычный вывод и сообщения об ошибках теперь разделены:

stdout  терминал
stderr  errors.txt

Можно отправить ошибки в /dev/null:

> find / -name "flag.txt" 2>/dev/null

В этом случае сообщения Permission denied и другие ошибки не показываются.



/dev/null

/dev/null - специальный объект, который используется для отбрасывания данных.

Например:

> echo "Hello" > /dev/null

Ничего не будет выведено на экран.

То же самое часто используется для ошибок:

> command 2>/dev/null

Можно представить это так:

данные
  ↓
/dev/null
  ↓
данные отброшены



Если команда выводит слишком много ошибок, иногда удобно использовать:

2>/dev/null

чтобы оставить на экране только полезный результат.



Конвейеры

Оператор | передаёт stdout одной программы в stdin другой.

Пример, как делать не нужно в связи с бессмысленностью:

> cat file.txt | grep "password"

Здесь:

cat
 ↓ stdout
grep
 ↑ stdin

То есть grep получает данные не с клавиатуры, а непосредственно от cat.

Но многие команды умеют работать с файлами напрямую, поэтому:

> grep "password" file.txt

часто проще.

Гораздо интереснее использовать конвейеры для объединения нескольких операций:

> cat users.txt | sort | uniq



Почему stderr не проходит через обычный |

Рассмотрим:

> command | grep "error"

Через | передаётся только stdout.

stderr продолжит выводиться отдельно, обычно прямо в терминал.

Если нужно объединить оба потока:

> command 2>&1 | grep "error"

Здесь:

2>&1

означает перенаправить stderr туда же, куда сейчас направлен stdout.

В Bash также можно встретить сокращённую запись:

> command |& grep "error"

Она предназначена для передачи в pipeline и stdout, и stderr.



tee

Иногда хочется одновременно увидеть вывод на экране и сохранить его в файл.

Для этого используется tee:

> ls | tee listing.txt

Результат появится на экране и одновременно будет записан в listing.txt.

Это удобно при исследовании системы, когда результат нужно и посмотреть, и сохранить.



Типовые конструкции

Сохранить результат команды

> command > output.txt

Добавить результат в файл

> command >> output.txt

Сохранить только ошибки

> command 2> errors.txt

Отбросить ошибки

> command 2>/dev/null

Передать результат другой программе

> command1 | command2

Передать вывод нескольким последовательным программам

> command1 | command2 | command3

Объединить stdout и stderr

> command 2>&1 | command2

Вывести и одновременно сохранить результат

> command | tee output.txt
