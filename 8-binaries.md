Бинарные и исполняемые файлы

До этого мы в основном работали с текстовыми файлами. Однако в Linux огромное количество данных хранится в бинарном виде. Бинарный файл - это файл, содержимое которого предназначено для интерпретации программой, а не обязательно для чтения человеком как обычного текста.

К бинарным файлам относятся изображения, архивы, библиотеки, исполняемые программы и так далее. При этом с технической точки зрения любой файл представляет собой последовательность байтов. Разница заключается прежде всего в том, как эти байты интерпретируются.

Бинарные и исполняемые файлы тесно связаны, и исполняемый файл могут зачастую называть бинарным, или просто "бинарником"/"бинарём". Однако исполняемый файл - лишь один из видов бинарных.



Текстовые и бинарные файлы

Рассмотрим обычный текстовый файл:

> cat hello.txt

Hello!

Его содержимое можно непосредственно воспринимать как текст.

Однако бинарный файл может выглядеть в терминале совершенно бессмысленно:

> cat image.png

На экран могут попасть непонятные символы и управляющие последовательности.

Для неизвестных файлов поэтому лучше использовать:

> file filename

Вы можете получить:

> file hello.txt 
hello.txt: ASCII text 

> file image.png 
image.png: PNG image data, 800 x 600 

> file program 
program: ELF 64-bit LSB pie executable, x86-64, ...



Исполняемые файлы

Исполняемый файл - файл, содержащий набор процессорных инструкций, который можно запустить.

Запуск несисемных программ на ОС Linux осуществляется следующим образом:

> ./program

Символы ./ перед фвйлом нужны, чтобы показать системе, что бинарник находится в текущей директории и его не нужно искать по стандартным системным путям, откуда обычно запускаются Linux-приложения. Такая запись валидна только при запуске программы из содержащей ее директории. В иных случаях необходимо указать относительный или абсолютный путь до программы.

Для запуска файла требуется право на выполнение (x в rwx) для текущего пользователя.

Как уже рассматривалось в теме прав доступа, выполнить файл можно после добавления соответствующего разрешения:

> chmod +x program



Исполняемый файл содержит не только машинный код. В нём также может находиться информация о структуре программы, используемых библиотеках и других необходимых для запуска данных.

В Linux наиболее распространённым форматом исполняемых файлов является ELF (Executable and Linkable Format), что и выведет вам утилита file, если вы встретите такой файл.



Исполняемый файл не обязан иметь расширение. В отличие от Windows, где имеют место такие расширения, как .exe и .dll, в Linux исполняемые программы зачастую расширения не имеют. Поэтому при анализе Linux-системы нельзя определять тип файла только по его имени.



Просмотр бинарных данных

Если необходимо посмотреть, из каких байтов состоит файл, удобно использовать xxd:

> xxd program

Например, начало ELF-файла выглядит примерно так:

00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000

Первые четыре байта:

7f 45 4c 46

образуют сигнатуру:

ELF

Это так называемая magic number — последовательность байтов, по которой можно определить формат файла.

Другие форматы также имеют характерные сигнатуры. Например, PNG начинается с:

89 50 4e 47

Поэтому шестнадцатеричный просмотр может помочь понять структуру и формат неизвестного файла.



Извлечение текста - strings

Бинарный файл не обязательно полностью состоит из нечитаемых данных. Внутри программы могут находиться строки:

Enter password:
Access denied
flag.txt

Их можно попробовать извлечь командой:

> strings program

Это очень простой, но полезный приём.



Если вам дали неизвестный исполняемый файл, одним из первых вариантов анализа может быть:

> file program
> strings program

Иногда нужная информация буквально хранится внутри программы в виде обычной строки.
