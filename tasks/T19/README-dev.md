# T19. Что здесь работает?

**Тема:** процессы · **Сложность:** 🟢 · **Время:** 5–7 минут

## Условие для студента

> В системе работают несколько фоновых процессов. Один из них запущен
> с секретным параметром — в нём и находится флаг.
>
> Разберитесь, какие процессы запущены и с какими аргументами, и
> найдите флаг.

Формат флага: `flag{...}`.

## Состояние контейнера

При старте контейнера запускаются три долгоживущих процесса
`/opt/worker` от имени пользователя `ctf`:

```text
/opt/worker --mode backup --secret flag{...}
/opt/worker --mode backup
/opt/worker --mode test
```

Пользователь-студент: `ctf`, cwd: `/home/ctf`. Демон `worker` ничего не
делает полезного — он просто ждёт, чтобы его можно было увидеть в
списке процессов.

## Флаг

```text
flag{process_argument}
```

Переопределяется переменной `TASK_FLAG` и передаётся процессу в
аргументах; в самом бинарнике флага нет.

## Ожидаемые навыки

`ps`, `ps aux`, `pgrep`, чтение командной строки процесса, при
желании — `/proc/<pid>/cmdline`.

## Подсказки

1. Посмотрите список процессов: `ps aux` или `ps -ef`.
2. Найдите процессы по имени: `pgrep -a worker`.
3. Обратите внимание на аргументы процессов — секрет передан
   отдельным параметром командной строки.

## Решение

```bash
ps aux | grep worker
# или
pgrep -a worker
# или
cat /proc/$(pgrep -f 'mode backup --secret' | head -n1)/cmdline | tr '\0' ' '
# ... flag{process_argument}
```

## Smoke test

```bash
docker run --rm linux-ctf/t19 sh -c 'test "$(pgrep -c worker)" -ge 3'
docker run --rm linux-ctf/t19 sh -c 'pgrep -af worker | grep -q "flag{"'
docker run --rm linux-ctf/t19 sh -c 'ps -o user= -p "$(pgrep worker | head -n1)" | grep -q ctf'
```

Проверяется: запущено не меньше трёх процессов `worker`, у одного из
них в аргументах есть флаг, процессы работают от имени `ctf`.
