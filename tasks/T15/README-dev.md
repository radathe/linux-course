# T15. Что это вообще?

**Тема:** типы файлов · **Сложность:** 🟢 · **Время:** 5–7 минут

## Условие для студента

> В домашнем каталоге лежит файл `mystery`. Он не похож на обычный
> текст, и открыть его редактором не получится.
>
> Разберитесь, что это за файл, и найдите флаг.

Формат флага: `flag{...}`.

## Состояние контейнера

```text
/home/ctf/
└── mystery            <- исполняемый ELF-файл, внутри есть флаг
```

Пользователь: `ctf`, cwd: `/home/ctf`. Файл исполняемый, владелец `ctf`.

Внутри бинарника, помимо реального флага, спрятаны строки-приманки
(например, ещё один `flag{...}`), поэтому «первый попавшийся» флаг
может оказаться ложным.

## Флаг

```text
flag{strings_are_useful}
```

Переопределяется переменной `TASK_FLAG`; в образе лежит только
плейсхолдер `flag{PLACEHOLDER_DO_NOT_SHIP}`, который заменяется
утилитой `patch_flag.py` при запуске контейнера.

## Ожидаемые навыки

`file`, `strings`, базовое представление о бинарных файлах и
исполняемых файлах ELF.

## Подсказки

1. Сначала определите тип файла — например, командой `file`.
2. Если это исполняемый файл, поищите внутри него читаемые строки:
   подойдёт утилита `strings`.
3. Отфильтруйте вывод по слову `flag` и отличите настоящий флаг от
   приманки.

## Решение

```bash
file mystery
strings mystery | grep flag
# flag{strings_are_useful}
./mystery
```

Настоящий флаг отличается от строки-приманки вида
`flag{this_is_a_decoy_do_not_submit}`.

## Smoke test

```bash
docker run --rm linux-ctf/t15 test -x /home/ctf/mystery
docker run --rm linux-ctf/t15 sh -c 'strings /home/ctf/mystery | grep -q "flag{"'
docker run --rm linux-ctf/t15 file /home/ctf/mystery
```

Проверяется: файл исполняемый, содержит строку с флагом, определён
как ELF.
