# T26. Маленький Linux CTF (итоговая)

**Тема:** итоговое повторение (ФС, архивы, бинарники, процессы, окружение, сеть) · **Сложность:** 🔴 · **Время:** 25–40 минут

## Условие для студента

> Это итоговая задача курса.  Единый флаг `flag{...}` собран из восьми
> фрагментов, и каждый фрагмент спрятан своим способом: в файлах и
> скрытых именах, в глубине каталогов, в архиве, внутри исполняемого
> файла, в аргументах и окружении запущенных процессов, а также в
> сетевом сервисе.
>
> Соберите все восемь фрагментов, расположите их в правильном порядке
> и получите целый флаг.
>
> В условии намеренно не указаны конкретные команды и точные пути —
> исследуйте систему самостоятельно.  Порядок фрагментов подсказывают
> сами места их находки.

## Состояние контейнера

```text
/opt/
├── data/
│   ├── README              <- подсказка к части 1
│   ├── .part1              <- скрытый файл (часть 1)
│   └── deep/
│       └── level1/level2/level3/level4/level5/
│           └── part2.txt   <- часть 2 (+ подсказка про архив)
├── backup.tar              <- архив: part3.txt (часть 3), encoded.txt (часть 4)
├── worker                  <- долгоживущий процесс (части 6 и 7)
├── tools/checker           <- ELF check26 (часть 5)
└── server.py               <- TCP-сервис 127.0.0.1:31337 (часть 8)
```

Пользователь: `ctf`, cwd: `/home/ctf`.

Все фрагменты читаются от имени `ctf`; ничего декодировать вручную из
бинарного формата не требуется.

## Флаг

```text
flag{linux_ctf_basics_are_easier_together_ok}
```

Флаг частями:

| Часть | Значение   | Где лежит |
|-------|------------|-----------|
| 1     | `flag{`    | `/opt/data/.part1` (скрытый файл) |
| 2     | `linux_`   | `part2.txt` в глубоком дереве |
| 3     | `ctf_`     | `part3.txt` внутри `/opt/backup.tar` |
| 4     | `basics_`  | `encoded.txt` в том же архиве (hex) |
| 5     | `are_`     | вывод `/opt/tools/checker` при верном коде |
| 6     | `easier_`  | аргумент процесса `/opt/worker` |
| 7     | `together_`| переменная окружения процесса `/opt/worker` |
| 8     | `ok}`      | ответ TCP-сервиса на `127.0.0.1:31337` |

Часть 5 внедряется в бинарник при старте контейнера утилитой
`patch_flag.py` (в образе лежит только плейсхолдер).  Роли частей 1–8
не переставляются: они складываются в осмысленную фразу.

## Ожидаемые навыки

Навигация по ФС и работа со скрытыми файлами; поиск файлов по системе;
распаковка архива; чтение строк из ELF-файла и запуск программы;
просмотр процессов и их аргументов; просмотр переменных окружения
процесса; сетевые подключения к локальному порту; кодирование/декодирование
hex.

## Подсказки

Ниже — восемь поэтапных подсказок, по одной на каждый фрагмент.
Конкретные команды не приводятся: выберите инструмент сами.

1. **Часть 1.** Рядом с файлом-инструкцией в каталоге данных есть
   скрытый файл (его имя начинается с точки).  Привычный просмотр
   каталога такие файлы не показывает — включите показ скрытых имён.
2. **Часть 2.** Второй фрагмент лежит в текстовом файле, который
   спрятан в дереве из нескольких вложенных каталогов.  Обойдите дерево
   целиком или найдите файл по имени; заодно прочитайте его подсказку
   про архив.
3. **Часть 3.** В корне системы есть архив-«резервная копия» с именем
   `backup`.  Посмотрите его содержимое и извлеките первый текстовый
   файл.
4. **Часть 4.** В том же архиве второй файл содержит фрагмент не
   текстом, а в шестнадцатеричном виде.  Переведите байты из hex в
   исходную строку.
5. **Часть 5.** Среди вспомогательных программ есть исполняемый файл.
   Извлеките из него печатаемые строки — среди них найдётся код
   доступа.  Запустите программу, передав ей этот код, и она выведет
   фрагмент.
6. **Часть 6.** Один из запущенных процессов получает фрагмент в
   качестве аргумента командной строки.  Просмотрите список процессов
   вместе с их аргументами.
7. **Часть 7.** Второй такой же процесс хранит фрагмент в переменной
   окружения (её имя — `SECRET`).  Переменные окружения работающего
   процесса можно прочитать через его запись в `/proc`.
8. **Часть 8.** На локальном порту `31337` слушает TCP-сервис.  Он не
   использует HTTP: при подключении сразу присылает последний
   фрагмент.  Соединитесь с ним подходящим инструментом.

## Решение

```bash
# Часть 1
ls -a /opt/data
cat /opt/data/.part1            # flag{

# Часть 2 (дерево и подсказка про архив)
find /opt/data -name 'part2.txt'
cat /opt/data/deep/level1/level2/level3/level4/level5/part2.txt   # linux_

# Часть 3 и 4 (архив)
tar -tf /opt/backup.tar
tar -xf /opt/backup.tar -C /tmp
cat /tmp/part3.txt              # ctf_
cat /tmp/encoded.txt            # 6261736963735f
printf '6261736963735f' | xxd -r -p   # basics_

# Часть 5 (бинарник)
strings /opt/tools/checker | grep -i code     # Correct code: ... / unlock-42
/opt/tools/checker unlock-42    # Correct code: are_

# Часть 6 и 7 (процессы и окружение)
ps aux | grep worker            # ... /opt/worker --fragment easier_
for p in $(pgrep worker); do tr '\0' '\n' < /proc/$p/environ; done
# SECRET=together_

# Часть 8 (TCP-сервис)
nc 127.0.0.1 31337              # ok}
```

Итог:

```text
flag{ linux_ ctf_ basics_ are_ easier_ together_ ok }
= flag{linux_ctf_basics_are_easier_together_ok}
```

## Smoke test

```bash
# Контейнер и пользователь
docker run --rm linux-ctf/t26 id -u

# Части 1, 2
docker run --rm linux-ctf/t26 bash -c \
  'cat /opt/data/.part1; cat /opt/data/deep/level1/level2/level3/level4/level5/part2.txt'

# Части 3, 4
docker run --rm linux-ctf/t26 bash -c \
  'tar -xf /opt/backup.tar -O part3.txt; tar -xf /opt/backup.tar -O encoded.txt'

# Часть 5
docker run --rm linux-ctf/t26 /opt/tools/checker unlock-42

# Части 6, 7 (фоновые процессы и сервисы; нужен запущенный контейнер)
docker run --rm -d --name t26 linux-ctf/t26 sleep 300
docker exec t26 bash -c 'ps aux | grep -F easier_'
docker exec t26 bash -c 'for p in $(pgrep worker); do tr "\0" "\n" < /proc/$p/environ; done' | grep SECRET

# Часть 8
docker exec t26 bash -c 'exec 3<>/dev/tcp/127.0.0.1/31337; cat <&3'
docker rm -f t26
```

Проверяется: контейнер стартует; присутствуют скрытый файл, глубокое
дерево, архив с двумя фрагментами, патченый `checker`, два процесса
`worker` (аргумент и `SECRET`) и TCP-сервис на `31337`.
