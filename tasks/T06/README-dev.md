# T06. Лишние данные

**Тема:** обработка текста (cut / sort / uniq) · **Сложность:** 🟢–🟡 · **Время:** 6–10 минут

## Условие для студента

> В файле `users.txt` находятся записи вида `имя:роль`.
>
> Часть имён повторяется.  Среди имён много «похожих на флаг» приманок,
> поэтому просто прочитать файл недостаточно.
>
> Получите отсортированный список **уникальных имён** и найдите среди них
> ключ — это строка ровно из 32 шестнадцатеричных цифр (`0-9`, `a-f`).
>
> Затем расшифруйте флаг:
>
> ```bash
> cd /home/ctf
> ./decrypt.sh <ключ>
> ```

## Состояние контейнера

```text
/home/ctf/
├── users.txt          <- 250-400 строк "имя:роль" с повторами и приманками
├── flag.enc           <- зашифрованный флаг
├── decrypt.sh         <- ./decrypt.sh <ключ>
└── README
```

Пользователь: `ctf`, cwd: `/home/ctf`.

Приманки специально похожи на флаг, но не совпадают с ним:
`SLS{secret}`, `ssl{secret}`, `SSl{secret}`, `SSL[secret]`,
`SSL(secret)`, `SSL-Secret`, `S5L{secret}`, `SSl{SeCreT}`, `SSL_secret`
и т. п.  Ни одна приманка не является корректным ключом.
Правильное имя-ключ в файле ровно одно.  Строки идут вперемешку, поэтому
визуальный просмотр не помогает — нужен конвейер обработки.

## Флаг

```text
SSL{text_pipeline}
```

Флаг хранится в `flag.enc` в зашифрованном виде и становится виден
только после `./decrypt.sh <ключ>`.  Открытым текстом в образе его нет.

## Ожидаемые навыки

`cut`, `sort`, `uniq`, `|`, `grep`.

## Подсказки

1. Имя пользователя — это часть строки до двоеточия.  Отделить её помогает
   `cut -d ':' -f 1`.
2. Чтобы убрать повторы, строки нужно сначала отсортировать, а затем
   применить `uniq` (или `sort -u`).
3. Настоящий ключ отличается от приманок строгим форматом: ровно 32
   маленькие шестнадцатеричные цифры.  Отфильтровать его можно через
   `grep -E '^[0-9a-f]{32}$'`.

## Решение

```bash
cut -d ':' -f 1 users.txt | sort | uniq
```

Найти среди уникальных имён настоящий ключ:

```bash
cut -d: -f1 users.txt | sort -u | grep -E '^[0-9a-f]{32}$'
# <ключ>
cd /home/ctf
./decrypt.sh <ключ>        # печатает SSL{text_pipeline}
```

## Smoke test

```bash
# 250-400 строк
docker run --rm linux-ctf/t06 bash -c \
  'test "$(wc -l < /home/ctf/users.txt)" -ge 250'
docker run --rm linux-ctf/t06 bash -c \
  'test "$(wc -l < /home/ctf/users.txt)" -le 400'

# приманки присутствуют, а корректного флага-строки нет
docker run --rm linux-ctf/t06 bash -c \
  'grep -q "SLS{secret}" /home/ctf/users.txt'
docker run --rm linux-ctf/t06 bash -c \
  '! grep -rq "SSL{" /home /opt /etc /usr 2>/dev/null'

# ровно один уникальный ключ из 32 hex; он расшифровывает флаг
docker run --rm linux-ctf/t06 bash -c \
  'test "$(cut -d: -f1 /home/ctf/users.txt | sort -u | grep -cE "^[0-9a-f]{32}$")" = 1'
docker run --rm linux-ctf/t06 bash -c \
  'cd /home/ctf && ./decrypt.sh \
     "$(cut -d: -f1 users.txt | sort -u | grep -E "^[0-9a-f]{32}$")"' \
  | grep -qx 'SSL{text_pipeline}'
```

Проверяется: файл достаточно большой, содержит приманки, открытого флага
в образе нет, после `sort -u` среди имён ровно один ключ из 32 hex, и
`./decrypt.sh` с ним печатает `SSL{text_pipeline}`.
