# T14. Испорченное сообщение

**Тема:** данные и кодирование · **Сложность:** 🟢 · **Время:** 5–7 минут

## Условие для студента

> В домашнем каталоге лежит файл `message.txt`. Его содержимое —
> сплошной набор латинских букв, цифр и знаков `=`; прочитать его
> как обычный текст не получается.
>
> Похоже, исходное сообщение было преобразовано в текстовый вид.
> Восстановите его и найдите флаг.

Формат флага: `flag{...}`.

## Состояние контейнера

```text
/home/ctf/
└── message.txt        <- кодированное сообщение с флагом
```

Пользователь: `ctf`, cwd: `/home/ctf`. Файл доступен на чтение всем.

## Флаг

```text
flag{base64_secret}
```

Переопределяется переменной `TASK_FLAG`. При запуске контейнера строка
`SECRET:password=<флаг>` кодируется и записывается в `message.txt`.

## Ожидаемые навыки

`cat`, распознавание кодированного текста, `base64` (`base64 -d`),
`grep`.

## Подсказки

1. Посмотрите на набор символов: он выглядит как стандартное
   представление двоичных данных в текстовом виде.
2. Это обратимое преобразование — существует утилита, которая
   декодирует такой текст обратно.
3. Декодируйте файл и поищите в результате строку вида `flag{...}`.

## Решение

```bash
cat message.txt
base64 -d message.txt
# SECRET:password=flag{base64_secret}
```

Или одной командой:

```bash
base64 -d message.txt | grep -o 'flag{[^}]*}'
```

## Smoke test

```bash
docker run --rm linux-ctf/t14 test -f /home/ctf/message.txt
docker run --rm linux-ctf/t14 sh -c 'base64 -d /home/ctf/message.txt | grep -q "flag{"'
docker run --rm linux-ctf/t14 id -un
```

Проверяется: файл существует, декодируется и содержит флаг,
пользователь — `ctf`.
