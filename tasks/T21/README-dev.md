# T21. Где настоящий вывод?

**Тема:** стандартные потоки · **Сложность:** 🟢 · **Время:** 5–7 минут

## Условие для студента

> В системе есть утилита `/opt/check`, которая «проверяет систему».
>
> Она печатает сообщения о ходе проверки, но, похоже, сообщает не всё:
> часть вывода уходит не туда, куда вы смотрите.
>
> Найдите флаг.

Программа запускается без аргументов: `/opt/check`.

## Состояние контейнера

```text
/opt/check        <- исполняемый скрипт (0755, ctf:ctf)
```

Скрипт пишет в **stdout** строки `Checking system...` и
`No problems found.`, а флаг — в **stderr**.

## Флаг

```text
flag{stderr_is_a_stream}
```

Переопределяется переменной `TASK_FLAG`.

## Ожидаемые навыки

Перенаправление потоков: `>`, `2>`, `2>&1`, `|`, а также
разделение stdout и stderr.

## Подсказки

1. У каждой программы есть три стандартных потока: stdin (0),
   stdout (1) и stderr (2).
2. Обычное перенаправление `>` захватывает только stdout.  Попробуйте
   сохранить отдельно stdout и отдельно stderr.
3. Слить оба потока вместе можно так: `команда 2>&1 | cat`, либо
   отправить только stderr в файл: `команда 2> файл`.

## Решение

```bash
# Показать только stdout (флага не видно):
/opt/check

# Слить stderr в stdout и увидеть всё:
/opt/check 2>&1

# Либо сохранить stderr отдельно:
/opt/check 2>/tmp/err
cat /tmp/err
```

## Smoke test

```bash
docker run --rm linux-ctf/t21 test -x /opt/check
docker run --rm linux-ctf/t21 bash -c '/opt/check 2>&1 | grep -q "flag{"'
docker run --rm linux-ctf/t21 bash -c '/opt/check 2>/dev/null | grep -q "No problems found."'
```

Проверяется: `/opt/check` существует и исполняем, флаг печатается в
stderr, обычные сообщения — в stdout.
