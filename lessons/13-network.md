Основы работы с сетью в Linux

Во многих CTF-задачах работа происходит не с локальными файлами, а с удалёнными компьютерами и сетевыми сервисами. Например, нам могут дать IP-адрес и порт, после чего предложить подключиться к программе и взаимодействовать с ней.

Для этого достаточно понимать несколько базовых понятий: IP-адрес, порт, клиент, сервер и сетевое соединение. Подробное устройство компьютерных сетей мы разберём в отдельном курсе, а здесь сосредоточимся на практической работе с сетью из Linux.



Основные понятия

IP-адрес используется для идентификации узла в сети.

Например:

192.168.1.10

Порт позволяет обратиться к конкретному сетевому сервису на этом узле:

192.168.1.10:8080

Здесь:

192.168.1.10 - адрес компьютера
8080         - порт

На одном компьютере одновременно могут работать разные сетевые программы:

порт 22 - SSH 
порт 80 - HTTP 
порт 443 - HTTPS 
порт 31337 - какой-либо CTF-сервис

Клиент и сервер

Упрощённо взаимодействие можно представить так:

клиент
   │
   │ запрос
   ↓
сервер
   │
   │ ответ
   ↓
клиент

Сервер - программа, которая ждёт входящие соединения.

Клиент - программа, которая подключается к серверу.



Проверка сетевого интерфейса - ip

Команда ip позволяет посмотреть информацию о сетевых интерфейсах и адресах компьютера.

Например:

> ip addr

или сокращённо:

> ip a

В выводе можно увидеть интерфейсы и назначенные им IP-адреса:

2: eth0: ...
    inet 192.168.1.15/24



Проверка доступности - ping

Команда ping отправляет запросы указанному узлу и позволяет проверить, отвечает ли он:

> ping example.com

Можно указать IP-адрес:

> ping 192.168.1.10

Пример:

64 bytes from 192.168.1.10: icmp_seq=1 ttl=64 time=0.5 ms
64 bytes from 192.168.1.10: icmp_seq=2 ttl=64 time=0.4 ms

При этом отсутствие ответа на ping не означает автоматически, что компьютер недоступен: ICMP-запросы могут быть заблокированы. Поэтому ping - это только один из способов первичной проверки.



Просмотр сетевых соединений - ss

Команда ss показывает сетевые соединения и слушающие порты.

Например:

> ss -lnt

Здесь:

-l → listening, ожидающие соединения
-n → показывать адреса и порты в числовом виде
-t → TCP

Можно увидеть что-то вроде:

LISTEN 0 128 0.0.0.0:22
LISTEN 0 128 127.0.0.1:8080

Это означает, что на машине есть программы, которые ожидают подключения к портам 22 и 8080.

Посмотреть более подробную информацию можно:

> ss -lntp



nc - Netcat

Netcat (nc) - один из самых полезных инструментов для работы с сетевыми соединениями в CTF.

Он позволяет устанавливать TCP-соединения и обмениваться данными практически вручную.

Самый простой пример:

> nc example.com 31337

Здесь:

example.com - адрес сервера
31337       - порт

После подключения можно вводить данные, а сервер будет отправлять ответы.

nc как простой клиент

Предположим, нам дали:

Host: challenge.example
Port: 31337

Подключение:

> nc challenge.example 31337

После этого взаимодействие может выглядеть так:

Welcome to the challenge!
Enter password:

Вводим:

> hello

и получаем ответ:

Wrong password

Таким образом, nc позволяет взаимодействовать с TCP-сервисом напрямую, не используя специальную клиентскую программу.



nc как сервер

Netcat может не только подключаться к серверу, но и сам ожидать входящие соединения.

Например:

> nc -l 12345

Здесь -l означает listen — ожидать подключения.

Теперь другая машина может подключиться:

> nc 192.168.1.15 12345

После этого можно передавать текст в обе стороны.



SSH

SSH (Secure Shell) — протокол и набор инструментов для безопасного удалённого доступа к компьютеру.

В CTF SSH часто используется как точка входа на удалённую Linux-машину.

Подключение:

> ssh user@host

Например:

> ssh alice@192.168.1.10

Здесь:

alice        - имя пользователя
192.168.1.10 - адрес сервера

После успешной аутентификации мы получаем удалённую shell-сессию:

локальный компьютер
       │
       │ SSH
       ↓
удалённый компьютер
       │
       └── Bash

И дальше работаем практически так же, как с локальным Linux:

> pwd
> ls
> whoami

Порт SSH

По умолчанию SSH использует порт 22.

Если сервер использует другой порт:

> ssh -p 2222 alice@192.168.1.10

где:

-p 2222 → подключиться к порту 2222



Передача файлов

Для передачи файла между компьютерами часто используется scp:

> scp file.txt alice@192.168.1.10:/home/alice/



curl

curl предназначен для взаимодействия с различными сетевыми протоколами. Особенно часто он используется для работы с HTTP и HTTPS. С помощью curl можно отправлять запросы веб-серверам, получать ответы, просматривать заголовки и передавать различные данные.

Например:

> curl https://example.com

Команда отправляет HTTP-запрос и выводит ответ сервера.

Если сервер возвращает HTML:

<html>
    <body>
        <h1>Hello!</h1>
    </body>
</html>

то именно этот текст мы увидим в терминале.

По умолчанию curl обращается по HTTP или HTTPS в зависимости от указанной ссылки.



Указание пути

URL может содержать не только имя сервера, но и путь:

> curl http://example.com/login

В этом случае запрос отправляется к ресурсу:

/login

Можно также передавать параметры в URL:

> curl "http://example.com/search?q=linux"

Здесь:

/search  → путь
q=linux  → параметр запроса

Кавычки особенно полезны, когда URL содержит специальные символы, которые могут интерпретироваться shell.



Получение HTTP-заголовков

Иногда содержимое страницы нас не интересует, а нужны только заголовки HTTP.

Для этого используется:

> curl -I http://example.com

Например:

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1250
Server: nginx

Заголовки могут содержать полезную информацию о сервере, формате ответа, cookies и других параметрах.

Можно также получить и заголовки, и тело ответа:

> curl -i http://example.com



Сохранение ответа в файл

Обычный вывод curl идёт в терминал. Ответ можно сохранить в файл:

> curl http://example.com > page.html

У curl есть и собственный параметр для сохранения результата:

> curl -o page.html http://example.com



Отправка данных

curl может использоваться и для отправки данных.

Например:

> curl -X POST -d "username=alice&password=12345" http://example.com/login

Здесь выполняется POST-запрос с указанными данными.

Подробно HTTP мы пока не изучаем. Важно понимать общую идею:



curl позволяет из терминала отправлять запросы серверу и получать его ответы.



Отправка JSON

При взаимодействии с API часто требуется отправлять JSON:

curl -X POST \
     -H "Content-Type: application/json" \
     -d '{"username":"alice","password":"12345"}' \
     http://example.com/api/login

Здесь используются две новые опции:

-H  → добавить HTTP-заголовок
-d  → передать данные запроса

В результате сервер получает:

{
    "username": "alice",
    "password": "12345"
}

Общий принцип: curl позволяет вручную формировать HTTP-запрос.



Cookies

curl позволяет работать с cookies.

Передать cookie вручную:

> curl -H "Cookie: session=abc123" http://example.com

Можно также сохранить cookies в файл:

> curl -c cookies.txt http://example.com

и использовать их позже:

> curl -b cookies.txt http://example.com

Это может быть полезно в CTF-задачах, где состояние пользователя хранится в cookie.



Аутентификация

Если HTTP-сервис использует простую Basic Authentication, можно передать учётные данные с помощью:

> curl -u alice:password http://example.com

curl сформирует соответствующий заголовок авторизации.



Просмотр подробностей соединения

При отладке запроса бывает полезно увидеть, что именно отправляет и получает curl.

Для этого используется:

> curl -v http://example.com

В выводе можно увидеть примерно:

> GET / HTTP/1.1
> Host: example.com
> User-Agent: curl/...
>
< HTTP/1.1 200 OK
< Content-Type: text/html
<
<html>
...

Это один из самых полезных режимов при исследовании веб-сервиса.





wget

Для загрузки файлов из сети часто используется:

> wget https://example.com/file.zip

После выполнения файл будет сохранён в текущий каталог.

В отличие от curl, который часто используется как универсальный инструмент для отправки запросов и получения ответов, wget особенно удобен именно для загрузки файлов.
