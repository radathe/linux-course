Права доступа

Теперь, когда мы знаем о пользователях и их привелегиях, можно перейти к правам доступа к файлам. Права доступа определяют, кто и какие операции может производить с данным файлом.



Предположим, команда ls -l secret.txt выводит:

-rw-r----- 1 alice developers 128 Sep 27 10:15 secret.txt

В этой строке несколько разных частей.

Самая важная сейчас:

-rw-r-----

Она описывает тип объекта и права доступа.

Первый символ этой строки - тип объекта. Для обычных файлов это -, для директорий d и т.п. Далее идут 9 символов: при полных правах на файл для всех пользователей они выглядят как rwxrwxrwx.

Linux разделяет пользователей, работающих с файлом, на три категории:

1. owner  - владелец файла
2. group  - пользователи группы файла
3. other  - все остальные пользователи

В нашем примере

-rw-r----- 1 alice developers ...

владелец:

alice

группа:

developers

Следовательно:

alice       - owner
developers  - group
все остальные - other

Для каждой из этих категорий могут быть назначены свои права, которые как раз и отображаются с помощью трехкратного rwx.



Права r, w и x

Для файлов используются три основных вида разрешений.

r — read

Разрешение на чтение содержимого.

Если у пользователя есть r, он может, например:

> cat file.txt



w — write

Разрешение на изменение содержимого файла.

Например:

> echo "hello" >> file.txt



Также, как | перенаправляет вывод одной команды на ввод другой, > и >> записывет вывод команды (в данном случае команды echo, по умолчанию просто выводящей текст в терминал) в файл. > полностью перезаписывает файл, а >> дописывает текст на следующую строку после уже существующего содержимого файла.



x — execute

Разрешение на выполнение файла как программы.



Как читать строку прав

Возьмём:

-rwxr-xr--

Первые 10 символов имеют специальную структуру:

- rwx r-x r--
  │   │   │
  │   │   └── other
  │   └────── group
  └────────── owner

Первый символ:

-

указывает на тип объекта.

Для обычного файла это -.

Для директории:

d

Для символической ссылки:

l

Оставшиеся девять символов разбиваются на три тройки:

rwx | r-x | r--
 ↑      ↑      ↑
owner  group  other

В нашем примере:

owner:  rwx
group:  r-x
other:  r--

То есть:

owner  - читать, изменять, выполнять
group  - читать, выполнять
other  - только читать



Права для директорий

Права r, w и x имеют немного другое практическое значение для директорий.

r

Позволяет просматривать список его содержимого.

Например:

> ls directory



w

Разрешает изменять содержимое каталога: например, создавать и удалять в нём файлы — при наличии необходимых остальных разрешений.



x

Позволяет обращаться к объектам внутри каталога и проходить через него.

Например

> cd directory

может требовать право x.



Числовая запись прав

Помимо буквенной записи существует числовая.

Основным правам соответствуют значения:

r = 4
w = 2
x = 1

Значения складываются.

Например:

rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 + 0 = 6
r-x = 4 + 0 + 1 = 5
r-- = 4 + 0 + 0 = 4

Такая запись исходит из бинарного представления прав - каждое из прав можно кодировать одним битом: либо право есть, либо его нет. Таким образом мы получаем трехзначное двоичное число, например:

rwx = 111 (в двоичной) = 7 (в десятичной)

или

r-x = 101 (в двоичной) = 5 (в десятичной)

Поэтому

755

означает:

7 → owner  → rwx
5 → group  → r-x
5 → other  → r-x

А

644

означает:

6 → owner  → rw-
4 → group  → r--
4 → other  → r--

Полезно уметь быстро переводить одну запись в другую.



Изменение прав - chmod

Для изменения прав используется команда chmod.



Изменение прав доступно только владельцу файла/директории и пользователю root.

Например:

> chmod 755 script.sh

После этого можно проверить результат:

> ls -l script.sh

Например:

-rwxr-xr-x 1 alice alice 120 Sep 27 10:20 script.sh



Символьный способ

Права можно изменять и буквами.

Добавить владельцу право на выполнение:

> chmod u+x script.sh

Здесь:

u → user/owner
g → group
o → other
a → all

Например:

> chmod g+w file.txt

добавит группе право на запись.

Удалить право:

> chmod o-r file.txt

Здесь:

+  → добавить
-  → убрать
=  → установить точно

Например

> chmod u=rwx,g=rx,o=r script.sh

устанавливает права точно:

owner → rwx
group → r-x
other → r--



Изменение владельца и группы

Помимо прав доступа можно изменить владельца файла.

Для этого используется команда chown.

> chown bob file.txt

Теперь владельцем файла является bob.

Можно одновременно изменить владельца и группу:

> chown bob:developers file.txt

Для изменения группы используется также:

> chgrp developers file.txt

Проверить результат:

$ ls -l file.txt
-rw-r----- 1 bob developers 128 Sep 27 10:15 file.txt



Что означает Permission denied

Сообщение:

Permission denied

не обязательно означает, что файл отсутствует.

Например:

> cat /home/bob/secret.txt

может вернуть:

cat: /home/bob/secret.txt: Permission denied

Файл существует, но текущий пользователь не обладает необходимыми правами.

Поэтому при появлении Permission denied полезно проверить:

> whoami
> id
> ls -l /home/bob/secret.txt

А также права на директории, через которые проходит путь к файлу.



Полезные команды для анализа пользователя и доступа

При получении доступа к Linux-машине полезно начинать с нескольких команд:

whoami
id
groups
pwd
ls -la
sudo -l

Они позволяют быстро понять:

кто я?
↓
какие у меня UID и группы?
↓
где я нахожусь?
↓
какие объекты здесь есть?
↓
какие права у этих объектов?
↓
какие дополнительные привилегии мне доступны?



Типичный CTF-сценарий

Предположим, мы нашли файл:

secret.txt

Но:

> cat secret.txt

возвращает:

Permission denied

Первый шаг - посмотреть права:

ls -l secret.txt

Получаем:

-r-------- 1 bob bob 42 Sep 27 10:15 secret.txt

Теперь видно:

owner → bob
owner permissions → r--
group → bob
group permissions → ---
other permissions → ---

Проверяем текущего пользователя:

> whoami

Получаем:

alice

Следовательно:

alice != bob

и для alice доступа на чтение нет.

В такой ситуации следующим шагом может быть исследование того, какие другие права и возможности есть у пользователя:

> id
> sudo -l

Дальнейшие способы получения доступа относятся уже к отдельной теме повышения привилегий (privilege escalation), что выходит за рамки базового курса, однако является интересной темой, которую вам, возможно, захочется изучить самостоятельно.
