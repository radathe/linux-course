Пользователи и привелегии

Linux рассчитан на работу с несколькими пользователями одновременно. Поэтому система должна контролировать, кто может читать, изменять и выполнять определённые файлы и программы. Для этого в Linux существуют пользователи, группы и права доступа.

Эта система особенно важна с точки зрения информационной безопасности. Один пользователь не должен автоматически получать доступ ко всем данным другого пользователя или к критическим файлам операционной системы. В CTF права доступа часто становятся частью самой задачи: например, нужный файл существует, но прочитать его может только другой пользователь, либо для выполнения определённой команды требуются дополнительные привилегии.



Пользователи и группы

Каждая запущенная программа в Linux выполняется от имени некоторого пользователя. Пользователь определяет, какие права получит программа при работе с файлами и другими ресурсами системы.

Для каждого пользователя существует уникальный идентификатор UID (User ID). Аналогично группы имеют собственные идентификаторы — GID (Group ID).

Узнать, от имени какого пользователя выполняется текущая сессия, можно с помощью:

> whoami

Например:

> whoami
alice

Это означает, что текущая сессия выполняется от имени пользователя alice.

Более подробную информацию предоставляет команда id:

> id
uid=1000(alice) gid=1000(alice) groups=1000(alice),27(sudo)

Здесь можно увидеть:

uid=1000(alice)     — UID пользователя alice
gid=1000(alice)     — основная группа
groups=...          — группы, в которые входит пользователь

Группы позволяют предоставлять одинаковый доступ сразу нескольким пользователям.

Например, можно создать группу developers и сделать определённые файлы доступными всем её участникам.

Посмотреть группы текущего пользователя можно отдельно:

> groups
alice sudo developers



Системные пользователи

Не все пользователи Linux являются людьми, сидящими за компьютером. Многие создаются для работы отдельных системных служб.

Например:

root
www-data
nobody

Программы могут запускаться от имени таких пользователей, чтобы ограничить их доступ к системе.

Это соответствует общему принципу информационной безопасности:



Программа должна обладать только теми правами, которые ей действительно необходимы.



Root и привилегии

Особым пользователем в Linux является root — суперпользователь системы.

В отличие от обычного пользователя, root обладает очень широкими полномочиями и может выполнять административные операции, недоступные обычным пользователям.

Проверить, является ли текущий пользователь root, можно обычной командой:

> whoami 
root

Однако в реальной работе редко требуется постоянно входить в систему как root. Вместо этого используется механизм временного получения административных прав.



sudo

Команда sudo позволяет выполнить отдельную команду с повышенными привилегиями, если текущему пользователю это разрешено.

Например:

> sudo cat /etc/shadow

При необходимости система может запросить пароль пользователя.

Важная идея:

обычный пользователь
        ↓
      sudo
        ↓
команда с повышенными правами

Это безопаснее, чем постоянно работать в привилегированной сессии.

Проверить, какие команды пользователь может выполнять через sudo, можно с помощью:

> sudo -l



В CTF после получения доступа к Linux-машине полезно узнать:

whoami
id
sudo -l

Последняя команда помогает понять, есть ли у текущего пользователя дополнительные разрешения.



su

Команда su позволяет переключиться на другого пользователя:



> su bob



В отличие от sudo, su обычно используется именно для смены пользователя, а не для выполнения одной отдельной команды.



Где Linux хранит информацию о пользователях

Базовую информацию о пользователях можно увидеть в:

/etc/passwd

Например:

> cat /etc/passwd
alice:x:1000:1000:Alice:/home/alice:/bin/bash

Эта строка содержит несколько полей, разделённых символом ::

alice       — имя пользователя
x           — поле пароля
1000        — UID
1000        — GID
Alice       — комментарий
/home/alice — домашний каталог
/bin/bash   — shell пользователя

Файл /etc/passwd не содержит непосредственно пароли пользователей в современных Linux-системах.

Информация о группах хранится в:

/etc/group

А данные, связанные с хешами паролей, обычно находятся в:

/etc/shadow

Доступ к /etc/shadow обычно ограничен.





/etc/passwd - это обычный системный файл, который во многих конфигурациях доступен для чтения обычным пользователям.

/etc/shadow содержит более чувствительную информацию и обычно защищён правами доступа.
