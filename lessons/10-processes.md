Процессы

Когда мы запускаем программу, например:

> ./program

на диске существует файл program, но для выполнения его код должен быть загружен в память. Операционная система создаёт для него процесс —-экземпляр выполняющейся программы.

Процесс можно рассматривать как «живую» программу: у него есть собственный идентификатор, состояние, выделенные ресурсы и контекст выполнения. Несколько процессов могут быть созданы из одной и той же программы и работать одновременно.



Главное различие

программа - файл на диске
процесс   - запущенный экземпляр программы

Например, файл /usr/bin/python3 - это программа, а запущенный через него Python-скрипт выполняется внутри процесса.



Как создаётся процесс

Упрощённо запуск программы можно представить так:

Пользователь вводит команду
          ↓
        Bash
          ↓
создаёт новый процесс
          ↓
запускается программа
          ↓
процесс выполняется
          ↓
процесс завершается

Например:

> ls

Bash получает команду ls, запускает соответствующую программу и ждёт её завершения. После этого shell снова выводит приглашение для ввода следующей команды.

Процессы могут создавать другие процессы. Поэтому в Linux существует отношение родительский процесс - дочерний процесс.

Например:

Bash
├── ls
├── grep
└── python

При этом процесс может запускать другие программы и создавать собственных потомков.



PID

Каждому процессу Linux присваивает уникальный в данный момент PID (Process ID).

Посмотреть процессы можно с помощью:

> ps

Например:

    PID TTY          TIME CMD
   1832 pts/0    00:00:00 bash
   2417 pts/0    00:00:00 ps

Здесь:

1832 → PID процесса bash
2417 → PID самого ps

Чтобы получить более подробную информацию:

> ps aux

Можно искать конкретный процесс:

> pgrep python

Например:

3178

Это означает, что процесс, соответствующий python, имеет PID 3178.



Состояние процесса

Процесс не обязательно постоянно выполняет инструкции. В разные моменты он может находиться в разных состояниях.

Упрощённо можно представить их так:

создан
   ↓
готов к выполнению
   ↓
выполняется
   ↓
ожидает ресурс / событие
   ↓
снова выполняется
   ↓
завершён

Процесс может, например, ждать ввода от пользователя или завершения операции с диском.

Некоторые состояния можно увидеть в выводе:

> ps aux

или:

> ps -e

Для интерактивного наблюдения удобно использовать такие утилиты, как top и btop. Лично я советую btop.



Как несколько процессов работают одновременно

Современный компьютер запускает множество процессов:

Bash
браузер
файловый менеджер
системные службы
антивирус
CTF-программа
...

При одном или нескольких ядрах процессора операционная система управляет тем, какой процесс получает процессорное время.

На практике это выглядит как одновременная работа большого количества программ:

Процесс A → CPU
Процесс B → ожидает
Процесс C → CPU
Процесс D → ожидает
...

Операционная система быстро переключается между процессами, создавая ощущение параллельного выполнения.

Посмотреть процессы в динамике можно с помощью:

> top

или, если установлен:

> htop

Например:

PID     USER   CPU%   MEM%   COMMAND
1832    alice   0.0    0.4   bash
2417    alice   2.1    1.2   firefox
3178    alice   0.0    0.3   python



Пользователь процесса

Процесс выполняется от имени определённого пользователя.

Например:

> ps -f

может показать:

UID      PID   PPID  CMD
alice    1832     1  bash
alice    3178  1832  python

Здесь:

PID  → идентификатор процесса
PPID → идентификатор родительского процесса

Всю ту же информацию вы можете увидеть в таких программах, как top, htop, btop и тому подобных.

Пользователь, от имени которого работает процесс, влияет на доступ программы к файлам и другим ресурсам.

Поэтому если программа запущена от root, она потенциально обладает гораздо большими возможностями, чем та же программа, запущенная от обычного пользователя.



Сигналы и завершение процесса

Процесс можно попросить завершиться с помощью команды:

> kill PID

Например:

> kill 4215

Несмотря на название команды, kill не означает исключительно «убить процесс». Она отправляет процессу сигнал.

Некоторые сигналы:

SIGTERM → попросить процесс завершиться
SIGKILL → принудительно завершить процесс
SIGSTOP → приостановить процесс
SIGCONT → продолжить процесс

Поэтому обычно сначала используют:

> kill 4215

а принудительное завершение:

> kill -9 4215

используют, когда обычное завершение не сработало.



kill -9 не даёт программе возможности корректно завершить работу и освободить ресурсы самостоятельно. Поэтому это не универсальный вариант «на всякий случай».



Завершение процесса

Когда программа заканчивает работу, её процесс завершается.

Например:

> sleep 3

создаёт процесс, который примерно через три секунды завершится.

После завершения управление возвращается Bash:

> sleep 3
>

Процесс может завершиться:





нормально;



из-за ошибки;



после получения сигнала;



после принудительного завершения.

При этом процесс возвращает код завершения, о котором мы уже говорили в Bash:

> echo $?

Например:

0

обычно означает успешное завершение.
